# Telegram Feedback Bot

Бот-посредник, который пересылает сообщения от пользователей администратору и позволяет отвечать им напрямую через функцию «Ответить» (Reply) в Telegram.

## Как это работает

1. Пользователь пишет боту сообщение.
2. Бот пересылает его администратору с именем и ID отправителя.
3. Администратор нажимает **Ответить (Reply)** на пересланное сообщение и пишет ответ.
4. Бот автоматически доставляет ответ пользователю от своего имени.

## Настройка

### 1. Создайте бота

1. Напишите [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot` и следуйте инструкциям.
3. Скопируйте полученный **токен**.

### 2. Узнайте свой Telegram ID

Напишите [@userinfobot](https://t.me/userinfobot) или [@getmyid_bot](https://t.me/getmyid_bot) — они пришлют ваш числовой ID.

### 3. Настройте переменные

Откройте `bot.py` и замените:
```python
ADMIN_ID = 000000000  # <-- Укажите ваш Telegram ID
```

## Запуск

### Локально

```bash
pip install -r requirements.txt
BOT_TOKEN=ваш_токен python bot.py
```

### На BotHost

1. Загрузите файлы на [bothost.org](https://bothost.org).
2. Укажите в настройках переменную окружения:
   - `BOT_TOKEN` = токен вашего бота
3. Запустите бота — он автоматически определит `Procfile`.

### На Railway / Render / VPS

1. Создайте проект и загрузите код.
2. Добавьте переменную окружения `BOT_TOKEN`.
3. Команда запуска: `python bot.py`.

## Команды бота

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие и начало работы |
| `/help` | Подсказка (для администратора — инструкция по ответам) |

## Структура файлов

```
telegram-bot/
├── bot.py              # Основной код бота
├── requirements.txt    # Зависимости Python
├── Procfile            # Для BotHost / Heroku-совместимых платформ
├── runtime.txt         # Версия Python
├── .env.example        # Пример переменных окружения
├── message_map.json    # Автоматически создаётся: привязка сообщений к пользователям
└── README.md           # Этот файл
```

## Важные замечания

- `message_map.json` создаётся автоматически и хранит привязку пересланных сообщений к ID пользователей. **Не удаляйте его** — иначе история ответов потеряется.
- После перезапуска бота старые сообщения (до перезапуска) остаются в `message_map.json` и работают корректно.
- Поддерживаются все типы сообщений: текст, фото, видео, голосовые, файлы и т.д.
